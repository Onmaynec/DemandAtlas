# Журнал изменений

## v0.4.0 — Security & Reliability (14.11.2026)

- Управляемые роли и ограничения по магазинам/категориям хранятся в БД.
- Bearer-ключи генерируются случайно, сохраняются только в виде SHA-256, имеют срок действия и могут быть отозваны или ротированы без перезапуска.
- Добавлен автономный администратор доступа, которому не доступны коммерческие метрики, прогнозы и закупки.
- Закрыта ситуация полной блокировки по истечении срока всех admin-ключей: локальная CLI recovery разрешена только при отсутствии действующих ключей и аудитируется.
- Создание первого администратора через offline bootstrap; управление пользователями, ключами и аудитом из API и отдельного экрана SPA.
- Защита от ошибочного запуска DEMO_MODE=1 и прежних статических TOKEN_* в APP_ENV=production.
- Rate limit по IP и credential с атомарными счётчиками PostgreSQL, очистка устаревших корзин через worker.
- Ограничение размера тела запросов, включая потоковые загрузки без Content-Length.
- Журналирование мутаций API (идентификатор запроса, актор, роль, маршрут, статус; без паролей/токенов и payload). Изменения учётных записей аудитируются в общей транзакции.
- Регрессионные тесты токенов, scoped-access, отключения, expiry, сценариев 401/403/409/413/429, а также PostgreSQL Compose smoke.

Ограничения: post-response аудит бизнес-запросов не атомарен; полноценные TLS/deployment, E2E browser и fault-injection recovery остаются открытыми.
