# ADR-0001: архитектура и публикация данных

Статус: принято для начального инкремента.

**Контекст.** Продукт должен работать локально без платного облака, сохранять происхождение данных и не выдавать невалидную витрину.

**Решение.** FastAPI + SQLAlchemy, PostgreSQL raw/staging/mart, отдельный Python-сервис прогноза, scheduler-worker и SPA.

**Целостность.** Raw и quality фиксируются даже для отклонённого batch. Staging, inventory, marts, dataset_version публикуются атомарно. Повтор продаж защищён составным ключом чека, а повторы команд idempotencyKey. Для утверждения плана используется оптимистическая версия и блокировка строки PostgreSQL.

**Компромиссы.** В первой версии синхронная публикация; для 3 млн фактов требуются измерения производительности, очереди и корректная переобработка изменённых исходных строк. Алгоритмы — прозрачные baseline, не подтверждение коммерческой точности на реальном рынке.

**Безопасность.** Серверная авторизация и ограничение scope обязательны; demo-токены подходят только для примеров. Production IAM отдельно.
