# DemandAtlas v0.4.0 — Security & Reliability

## Серверная авторизация

Добавлены хранимые в БД учётные записи, роли, разрешённые магазины и категории. Ключи генерируются криптографически безопасным генератором, сохраняются как SHA-256 отпечатки, возвращаются только при создании или ротации. Действуют сроки годности, отзыв и немедленное отключение пользователя. Новая самостоятельная роль access_admin имеет доступ только к управлению учётными записями и журналу, не к бизнес-показателям.

Для первой учётной записи используется локальная команда python -m backend.scripts.manage_access bootstrap --name operator. API после этого позволяет создавать пользователей, назначать ограничения, выпускать, ротировать и отзывать ключи. В браузере доступна отдельная вкладка «Управление доступом» с журналом действий.

В APP_ENV=production система запрещает DEMO_MODE=1, статические демонстрационные токены и стандартный FORECAST_SERVICE_TOKEN. Прежние demo-engineer/demo-analyst и другие демонстрационные ключи работают только при явном локальном DEMO_MODE=1.

## Защитные механизмы

- Регистрируются изменяющие API-запросы: actor, роль, маршрут, HTTP статус, requestId и время. Тело запроса и Bearer-ключи не записываются. Управление доступом аудитируется в той же транзакции, что и изменение.
- Rate limiting теперь использует атомарные счётчики в PostgreSQL/SQLite и действует для нескольких API экземпляров; применяется лимит по клиентскому IP и по отпечатку credential за минуту.
- POST/PATCH/PUT защищены верхней границей размера данных, в том числе при chunked request.
- Административная роль не наследует права чтения аналитики, прогнозов или закупок. Новые тесты проверяют отрицательные кейсы.

## Проверки

Добавлены интеграционные проверки создания, ротации и отзыва ключей, сроков действия, блокировки пользователя, ограничений store/category, защиты от отключения последнего администратора, отказа демо-ключам, размера запроса, rate limiting и аудита. PostgreSQL Compose дополнен интеграционным smoke для managed identity.

## Ограничения

Сервис всё ещё распространяется как локальная Docker Compose конфигурация с учебными секретами; внешнее production-развёртывание требует TLS, секрет-хранилища, резервных копий, мониторинга, усиленного межсервисного доступа и полноценного браузерного E2E. Аудит обычных бизнес-мутаций выполняется после ответа; при отдельном сбое записи события сервер сообщает ошибку в логах, но операцию не отменяет. Тесты аварийного восстановления и целевая нагрузка 3 млн строк пока не завершены.
