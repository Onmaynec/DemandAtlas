# DemandAtlas v0.2.0 — Data Integrity

## Целостность данных

При повторном импорте чека проверяются ключ sourceId/transactionId/lineId и его атрибуты. Совпадающие записи повторно не учитываются и не увеличивают версию набора. Изменение количества, цены, магазина, SKU, даты, промо или сток-аутов блокирует batch: качество фиксирует changed_published_fact с номером строки.

Для исправлений доступна отдельная подтверждённая замена диапазона source/store/date с expectedDatasetVersion, причиной и idempotencyKey. Она атомарно обновляет staging и затронутые mart, но сохраняет старые raw и опубликованные прогнозы. Пустой подтверждённый snapshot позволяет описать дни с нулевыми продажами.

## Аналитика и интерфейс

Добавлены API для переобработки, версии dataset и списка пропущенных магазин-дней. В SPA — форма корректировки CSV с подтверждением, детальный coverage и журнал режимов. Выгрузка CSV нейтрализует формулы.

## Проверки

Тесты 100 ошибочных строк, 3 пропущенных дней, повторов и конфликтов, замены, отката и доступа. CI включает Python, Docker, PostgreSQL Compose и конкурентные запросы.

## Ограничения

Требования по скорости на 3 млн записей, production IAM, durable очередь и disaster recovery пока не подтверждены. Это функциональное обновление, а не финальная приёмка PV-DATA-05.
