# ADR-0002: конфликтующие дубли и snapshot-переобработка

Статус: принято для v0.2.0.

## Проблема

В v0.1.0 ON CONFLICT DO NOTHING не отличал точный повтор чека от изменённой продажи. Новый источник мог попытаться исправить старое значение, но витрина оставалась прежней без понятной ошибки.

## Решение

Сравнивать атрибуты идентичного чека после блокировки dataset_state. Изменение публикуемых ключей — критический finding, который блокирует весь batch. Законное исправление оформляется отдельной полной заменой source/store/date с optimistic concurrency по dataset_version, идемпотентным ключом и причиной. Все затронутые SKU пересчитываются из staging по всем источникам одной транзакцией.

## Последствия

Менеджер получает проверяемый протокол изменений. Разрешена только замена полного авторитетного среза, а не одиночный patch. Прогнозы, опубликованные до коррекции, остаются с исходным dataset_version. Коррекции требуют повторного расчёта новых прогнозов.

## Не закрыто

Durable очереди, fault injection процессов, production IAM и масштабный нагрузочный профиль.
